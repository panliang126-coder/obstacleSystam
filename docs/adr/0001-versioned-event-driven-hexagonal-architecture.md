# ADR-0001：版本化事件驱动六边形架构

- 状态：Accepted
- 日期：2026-07-27
- 决策者：项目架构基线

## 背景

系统需要在模拟器、回放、HIL 和真实设备之间切换，并允许感知、天气、风险、规划和决策算法独立升级。传感器频率、时间基准、坐标、可靠性和厂商 SDK 均不同；如果业务模块直接调用设备或彼此内部对象，后续真实设备接入会要求重构上层逻辑，也难以进行确定性回放和故障注入。

## 决策

1. 采用六边形架构：领域与应用逻辑只依赖 `ports/`，厂商 SDK、Broker、数据库、GUI 和飞控属于 Adapter。
2. 跨模块采用 Event Bus；消息使用版本化 Envelope，包含事件/链路/因果/运行/来源/时间/质量。
3. JSON Schema 2020-12 是 v1 可读与运行时校验契约；protobuf 遵守向后兼容字段编号规则。
4. 真实 Driver 与 Simulator 实现同一端口，并运行同一契约测试。
5. 插件使用声明式 manifest 和生命周期；学习插件不能绕过独立 Validator、Safety Gate 或 Control Gateway。
6. `SIM/REPLAY` 不能连接真实控制端点；Control Gateway 是唯一飞控出口。

## 备选方案

### 模块直接 RPC

拒绝。会把部署拓扑固化到业务接口，并使回放、进程合并和算法替换困难。

### 全部使用 ROS2 原生消息作为领域模型

拒绝作为唯一内部模型。ROS2 可作为 Adapter，但领域契约需同时支持非 ROS 的边缘、云端、数据库和回放工具。

### 只使用 protobuf

暂不采用。protobuf 适合高效传输，但 JSON Schema 更便于早期审阅、样例、配置和多语言调试；两者保持语义映射。

### 共享数据库集成

拒绝。共享表会绕过事件、权限和版本边界，产生隐式耦合。

## 结果

正面：

- 模拟/真实设备可替换；
- 消息可验证、可审计、可回放；
- 单机与多进程部署不改变领域接口；
- 插件和服务故障可隔离。

代价：

- 需要维护 Schema/protobuf 双表示和兼容测试；
- 至少一次消息语义要求幂等、Outbox/Inbox；
- 坐标、时间和质量字段增加实现复杂度。

## 兼容与迁移

- v1 minor 只新增可选字段；major 变更需双读/双写和 upcaster。
- 已发布 protobuf field number 永不复用。
- 旧事件永久保留原始 Schema 版本。

## 回滚

可以替换 Event Bus、数据库或 Adapter，但不回滚版本化领域契约、控制隔离和真实/模拟同构原则。若本 ADR 被替代，新 ADR 必须提供消息、数据和部署迁移方案。
